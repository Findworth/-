需求分析：
电商产品案例：Temu / 拼多多

一、产品定位与差异化
核心特点：全托管模式 + 极致低价

二、需求拆解（五要素：背景·用户·场景·目标·数据）

需求1：降低跨境电商门槛
· 背景：跨境卖家需独立完成营销、流量、测品、投放、收款、售后、物流等，门槛高
· 用户：想出海但缺乏专业能力的卖家
· 场景：从选品到履约的全链路
· 目标：让卖家专注供货，平台承接运营
· 方案：将平台的业务触角向上下游延伸，积极抢占过去本属于跨境电商专业服务商和卖家的价值空间，即全托管模式——卖家仅供货，平台负责营销/流量/测品/投放/收款/售后/物流，平台直面海外消费者
· 类比：类似于沃尔玛，沃尔玛对供应商的绝对话语权
· 中国供应链红利：充分利用国内完整、高效的供应链体系，成本低（这也是当年沃尔玛供应商在中国设厂的根本原因）
· 不足：术业有专攻，各环节、各目的国的垂直能力未必最优，仍有新玩家空间

需求2：满足低价刚需
· 背景：对多数消费者，价格优先于情感等非价格因素
· 方案：极致低价——依托全托管压榨供应商利润、国内供应链优势、去中间商

【数据指标】AI Agent 指标设计

一、技术类指标
1. 平均响应时长：请求到完整响应的间隔
2. 转人工率：需转人工的会话占比
3. 错误率：API调用失败占比
4. 发现次数：Agent发现店铺数（如google UCP协议）
5. 查询转化率：查询次数 / 发现次数
6. 结算创建率：结算次数 ÷ 浏览商品事件数
7. 最终转化率：完成订单数 ÷ 发现事件数
8. 订单总收入：Agent路径完成的GMV

二、用户体验指标
1. 退货率——发生退货的订单占比
2. 推荐结果采纳率——用户点击了Agent推荐的某个商品/链接的次数 ÷ Agent总推荐次数
3. 平均客单价——Agent引导成交的订单的平均金额

三、指标如何指导迭代
技术类：响应时长异常→优化API/流式/缓存；转人工率高→增强意图理解与上下文工程；错误率高→排查接口与重试；漏斗转化低→定位断点优化；订单总收入→衡量商业价值与资源优先级
体验类：退货率高→优化推荐与匹配；采纳率低→改进策略与展示；客单价低→加强关联推荐与促销

【统计学】产品应用

概念与产品应用：
   1. 方差/标准差：数据围绕平均值的离散程度，值越大说明波动越剧烈。
      产品应用：评估功能上线后某指标（如日活、留存）的稳定性。若某版本标准差明显增大，说明用户行为波动变大，需排查是否引入不稳定因素。

   2. F1 score：精确率和召回率的调和平均，用于在"漏判"和"误判"之间找平衡。
      产品应用：内容推荐/风控策略。如推荐系统既要少推无关内容（精确率），又要尽量覆盖用户可能喜欢的（召回率），F1 帮助综合评估模型效果，指导调参或策略取舍。
      购物Agent应用：Agent根据用户意图推荐商品时，精确率=推荐中用户点击/加购的比例，召回率=用户可能感兴趣的商品中被推荐到的比例。
                     精确率低→推了一堆不相关货，体验差；召回率低→漏推好货，转化损失。用F1综合评估推荐策略，在"少推错"和"多推对"之间找平衡，指导意图理解、商品匹配等调参。

   3. 中心极限定理：从总体中多次抽样，每次算一个样本均值，这些样本均值的分布会趋近正态分布（钟形曲线），与总体本身是什么分布无关。
      举例：用户单次付费金额是典型的右偏分布（多数人花几十块，少数人花几千），本身不是正态。但若我们做 1000 次实验，每次随机抽 500 人算平均付费，这 1000 个"平均付费"会近似正态分布。
      产品应用：A/B 实验中，即使用户转化率、人均时长等指标本身不服从正态分布，大量用户的样本均值近似正态，可用 t 检验、z 检验做显著性判断，得出"实验组是否显著优于对照组"的结论。
      一般步骤：
      1. 根据问题，提出H0假设
      2. 给定显著水平，和样本数量
      3. 构造合适的检验统计量，明确在H0成立的分布
      4. 求出P-显著水平时的拒绝域
   例子：
   1. 在A/B测试中，假设A产品正常工作时，用户人均时长服从正态分布(已知均值/方差)，现做了新的B产品，有了样本数据，现考虑均值变化
   2. H0假设：B均值与A均值一样
   3. 构造t检验统计量，确定显著性指标alpha
   4. 在给定显著性水平 α 下，求出拒绝域；或计算 p 值，与 α 比较。
   5. 得到最终结果：A/B的均值是否相同

   4. 贝叶斯定理：根据新证据更新对某事件发生概率的判断。
      产品应用：用户转化预测。如已知某渠道历史转化率（先验），当用户完成某行为（如加购、浏览时长）时，用贝叶斯更新其转化概率
      A/B 测试应用：
      1. 情况说明：有一个新功能，在正式上线前，不知道它好不好，做了A/B测试，实验结果显示这个功能显著提升了用户参与度，问题是：看到这个“显著提升”的结果后，有多大把握认为这个功能真的成功了？
      2. 关键概率：
         1. 实验前，我们相信“功能成功”的概率（先验概率）：P(S)
         2. 如果功能真的成功，A/B测试能观察到“显著提升”的概率：P(D | S)
         3. 如果功能其实没用，A/B测试却“碰巧”观察到显著提升的概率：P(D | 非S)
         4. 利用贝叶斯公式(全概率定理，计算分母：无论成功与否，出现这种测试结果」的总概率)，计算得出 P(S|D)=0.9，这说明 在观察到数据D（显著提升）后，功能S成功的概率
         5. 测试前：P(S) = 0.5，看到「参与度显著提升」后：P(S|D) = 0.9
            也就是说，在观察到这次 A/B 测试结果后，功能真正成功的概率从 50% 更新为 90%。


【对话产品指标】只关注整体可用率的问题
   1. 掩盖质量差异：能连上≠好用，回答跑题、幻觉、答非所问仍会流失用户 
   2. 忽视响应速度指标：可用但每次等20秒，对用户几乎不可用
   3. 引发错误返回结果：为拉高可用率倾向兜底回复、简单模板，导致"可用但没用"
   4. 忽视失败类型：超时、限流、内容过滤等失败原因不同，对体验影响不同，混在一起无法定位
   5. 整体可用率是平均数，会掩盖“大多数对话很好，少数对话极差”的情况，可能在处理复杂问题时，可用率较低，而简单问题则较高


【像做自媒体一样做Agent】购物Agent分享策略

1. 降低分享门槛：支持分享到微信、朋友圈、小红书等（类比抖音/小红书）
2. 内容质量优先：用研究工具(deepsearch)生成报告，一键导出，干货才有分享动力
3. 预设分享选项：类比话题/标签，如好物清单、避坑指南，主动引导
4. 分层激励：分享后奖励分级，如高级模型token、agent可访问货源
5. 热点文案：结合抖音/小红书热点梗生成分享文案
6. 投票机制：选品时分享到朋友圈/社区，朋友投票，卡片形式
7. 一键生成：参考小红书AI生图，agent生成分享卡片封面
8. 虚拟试穿：真人出镜有说服力，AI虚拟试穿一键分享
9. 图文/视频优先：自媒体推流更好
10. 针对不同平台做优化，比如小红书女性受众偏多，封面可以偏暖色，内容可以更加丰富
